Start here

You have about 20 files, and you want ChatGPT, Claude, or NotebookLM to answer from them. This path needs no terminal. Do the three moves, then upload the folder. The numbered steps further down are the full method.

1. Keep only the current file

For each document, keep the copy you would stand behind today. Put older drafts somewhere you will not upload: names with final, v7, latest, copy, or (1) are the usual clues. If two files disagree, ask the owner which one is current. If nobody will say, keep the latest approved copy and write that choice down.

2. Make sure you can select the words

Open each PDF and drag across a sentence. If real words highlight, the file is ready. If nothing selects, or the copy is nonsense, the page is a picture. Run text recognition (OCR) so the file gains a text layer, then read one page of the result next to the original. Word files, Google Docs, and plain text you can already read can skip this move.

  • Mac, Preview. Open the PDF, choose File > Export, and select Embed Text if that checkbox is shown. Save a new file. Apple’s Preview guide documents this on macOS Ventura and later. The checkbox appears when the PDF does not already contain recognized text. The saved file can be selected in other viewers.
  • Adobe Acrobat. Choose All tools > Scan & OCR, then In this file, then Recognize text, and save. Menu labels move between versions; look for Scan & OCR and Recognize text. Those commands are in Acrobat, the paid editor. The free Acrobat Reader does not include them.
  • Google Drive. On a computer, upload the scan, right-click it, and choose Open with Google Docs. Google’s help says the file should be 2 megabytes or smaller, right-side up, and sharp, and that tables and columns often do not come through. Compare the Doc with the scan, including the last pages. To make a PDF of the Doc, choose File > Download > PDF Document (.pdf). You can also add the Doc itself as a NotebookLM source.
  • Word, opening a scan. Choose File > Open and open the PDF. Word converts a copy and tries to recover the words. Microsoft says this works best when the page is mostly typed text, and that you should proofread. Handwriting usually fails. The original PDF is left unchanged.
  • A document you typed. Saving as PDF keeps words that are already text. A photograph of a page still needs the recognition steps above. In Word, choose File > Save As or Save a Copy and pick PDF, or choose File > Export > Create PDF/XPS. In Apple Pages, choose File > Export To > PDF. On a Mac you can also choose File > Print, then PDF > Save as PDF. On Windows, print and choose the printer Microsoft Print to PDF. In LibreOffice, choose File > Export As > Export as PDF.
  • One picture of a page. On a Mac, open it in Preview and copy the words if you can select them, then paste them into a document. On Windows 11, open the picture in the Photos app and use Scan text if that button is there. The Microsoft Lens app on a phone can save a scan as a Word document. Read the result.

3. Name each file with a date

Put the date printed on the document first, as year-month-day, then a short name with hyphens: 2024-11-01_travel-policy.pdf. Leave final, latest, and new out of the name. Keep passwords, customer secrets, and home addresses out of the name too. Names show up in search results and in the chat’s citations.

Ask from those files

Put the prepared files in one folder and upload that set. In NotebookLM, create a notebook and add the files as sources. About 20 files is a comfortable set. A PDF locked against copying can be refused; if you are allowed to, open it and save a new PDF. In ChatGPT or Claude, attach the files in the chat. If the account has Projects, add the files there so the next question uses the same set.

Ask a question you already know the answer to. If the reply is empty or wrong, look for a missing text layer or an old draft still in the folder before you rephrase the question.

Uploading sends a copy of the files to that company. Leave out secrets, and leave out any file the people using the chat are not allowed to see. Step 11 is the longer version of that rule.

Why preparation matters

This guide is for people who already have a pile of files: a shared drive, an exported mailbox, a wiki dump, a folder of contracts. Search and language models can only use the text you give them. They do not know which copy is current. They cannot read a photograph of a page until something has recognized the letters. They will repeat a password, a home address, or an old policy if that text is in the index.

Most bad answers start in the files, before anyone writes a prompt. Duplicate drafts compete with the real document. Scans have no text layer. Tables get read across the wrong way. Every email reply contains the whole thread again. Dates are missing, so nothing can tell the 2019 draft from the rule in force.

Preparation is ordinary library work. You decide what is in scope, keep one current copy, turn it into clean text with a title and a source, and check that a real question finds the right passage. The steps below are enough to start with common tools. Work them in order. Skip a conversion step when you do not have that kind of file, and still run the checklist so the skip was a choice.

Each numbered step opens with a short “Just do this.” The commands and the longer notes are in Power-user version on that same step.

Tool names below are starting points. Commands change between versions. If a flag differs from what you have installed, the project’s own --help wins.

Target formats

Pick one text form for the index and keep the original file as the record people still edit or sign. The text form is what search and the model read. For a small upload to a chat, Start here is enough when the words in each file are already selectable.

Recommended target for each kind of file. Keep the original next to the text.
You have Store this for the index Why this form
Text PDF Markdown or UTF-8 text, plus the PDF The words are already in the file. The PDF stays the record.
Scanned PDF A searchable PDF, then Markdown or UTF-8 text OCR adds a text layer. Models cannot read the picture alone.
Email .eml or .mbox, plus a cleaned text copy Headers stay intact. The text copy is what you index.
Word, ODT, RTF, HTML Markdown Headings survive and give you sections to split on.
Plain text UTF-8 text with LF line endings Stops encoding damage and noisy diffs.
Spreadsheet CSV, one table per file, plus a column note Each row means one thing, and each column has a name.
Slides Markdown, one section per slide Titles, body text, and speaker notes become readable.
Image or photo of a page The image, a caption, and OCR text if it contains words Search sees the caption and the recognized text.

Step 1

Inventory and scope

Why You can only prepare a collection you have listed. Indexing everything also pulls in drafts, personal mail, and files a smaller group was meant to see alone.

Just do this

Write down every place the files live: a folder on your computer, a shared drive, a wiki, a mailbox. Next to each place, note who owns it and whether you will include it. Leave out personal mail, drafts you would not stand behind, and anything a contract or legal staff say must stay out. A spreadsheet or a note is enough. Name one person who can answer for this corpus, the set you are about to prepare.

Power-user version: full notes for this step

How

  • List every place documents live: shared drives, SharePoint or Google Drive exports, wikis, ticket exports, local project folders, and mail archives.
  • For each collection, write the path, the kinds of files, the date range, the owner, and whether people still treat that place as the source of record.
  • Mark each collection in or out. Out includes drafts you will not stand behind, personal mailboxes, copies of a system you already included, and anything legal or contract staff say must stay out.
  • Name one owner for the prepared corpus, and keep the owner of each source collection. Someone has to answer “is this the current file?”

A spreadsheet is enough. Suggested columns: location, file types, date range, owner, in or out, reason, sensitivity. This is a decision record. It does not need to be a cataloging system.

Step 2

Clean up

Why Duplicates and old drafts compete with the current document. Search then returns several answers, and the longest one is often the wrong version.

Just do this

Keep one current copy of each document. Move older drafts and extra copies into a folder you will not upload, or delete them when retention rules allow. Leave out junk the computer adds on its own, such as .DS_Store, Thumbs.db, Word lock files whose names start with ~$, and empty files.

Power-user version: full notes for this step

How

  • Find exact copies by file content. fdupes groups files that are byte-for-byte identical. Keep one copy of each group.
  • Find near copies by hand where the names give them away: final, v7, latest, dates, and (1). Ask the owner which file is current. If nobody will say, keep the latest approved copy and write that rule in the inventory.
  • Move rejected copies to a folder you do not index, or delete them when retention rules allow. Leave them out of the folder you will convert.
  • Remove junk an indexer would treat as documents: .DS_Store, Thumbs.db, desktop.ini, Word lock files (~$*), .tmp files, empty files, and installer logs.

Step 3

Folders and file names

Why The path becomes part of the citation. A person and a retrieval system both need to see which document a passage came from.

Just do this

Give each collection its own folder, and keep the path short: the collection, then a year or a topic, then the file. Name the file with the date first, as year-month-day, then a short hyphenated name, as in 2024-11-01_travel-policy.md. The current folder holds the current files. Keep passwords and home addresses out of names. Add a few lines in a README saying what the folder contains, who owns it, and what “current” means.

Power-user version: full notes for this step

How

  • Use one collection per top folder: policies, contracts, meetings, support.
  • Stay shallow. Collection, then year or topic, then the file is enough.
  • Use lowercase names with hyphens. Put an ISO date first when the date identifies the document: 2024-11-01_travel-policy.md.
  • Leave final, latest, and new out of names. The current folder holds the current files. Older copies live in an archive folder you do not index.
  • Add a short README in each collection: what it contains, who owns it, and what “current” means.
  • Keep secrets and personal data out of file names. Names show up in logs, citations, and search results.

Step 4

Metadata

Why Title, date, author, source, type, and permissions tell you what a retrieved paragraph is and who may see it. A file’s modified time is a weak substitute for the date on the document.

Just do this

For each document, write the title a person would use, the date printed on it as year-month-day, who issued it, where this copy came from, the kind of document, and who may read it. Put that block at the top of the text file, or in a sidecar file beside it, such as travel-policy.meta.txt. The date on the document matters more than the date the computer last saved the file.

Power-user version: full notes for this step

How

Put a header at the top of each text file, or a sidecar with the same stem, such as travel-policy.meta.txt. Use the date printed on the document when it differs from the file timestamp.

  • title — the name a person would use.
  • date — the document date, as YYYY-MM-DD.
  • author — a person or the team that issued it.
  • source — where this copy came from: a URL, a library path, or a message id.
  • type — a short list you actually use: policy, contract, email, minutes, spreadsheet, how-to.
  • permissions — the audience: public, internal, or a named group such as hr.

Keep a stable id if you rename the file, so a later update replaces the same document. A permission label does nothing until the search application filters on it. Step 11 is where that filter has to hold.

Step 5

PDFs

Why A PDF is a picture of a page plus, sometimes, a hidden text layer. If the text layer is missing or scrambled, extraction returns blank pages or nonsense, and the model has nothing true to quote.

Just do this

Open the PDF and try to select a sentence. If real words highlight, you can use the file. If selection fails, or the copied words are nonsense, follow the recognition steps in Start here, then read one page of the result beside the original. When the meaning is in a table, check that table against the PDF. A plain extractor often reads across a row the wrong way, and it glues the page header onto the text.

Power-user version: full notes for this step

How

Text PDFs and scanned PDFs

Open the file and try to select a sentence. If you can copy real words, it is a text PDF (sometimes called born-digital). If selection fails, or the copied text is gibberish, the page is a scan or a broken export.

Confirm from the command line with Poppler’s pdftotext. A text PDF prints words. A scan prints almost nothing.

Default pdftotext rebuilds reading order, which is what you want for prose. Add -layout when you need to see columns while you check a page. -layout pads lines with spaces, so it is a poor file to chunk as-is. Page breaks are form-feed characters; leave them in if you want to cite a page number. -nopgbrk removes them.

Some PDFs have a text layer that is still wrong, because the font encoding is damaged. If the words look garbled, treat the file like a scan and OCR it.

OCR with Tesseract and OCRmyPDF

Tesseract reads an image of text. OCRmyPDF runs Tesseract on a PDF and writes a searchable PDF with the text hidden behind the page image. Keep the original scan, and write the OCR result beside it.

Set the language. Quality drops when the language is wrong. Combine languages with a plus sign when a document mixes them. --deskew straightens pages that were scanned slightly crooked. --sidecar also writes a plain-text file.

OCRmyPDF stops when a PDF already has text, so a mixed file (some real text, some scans) needs --skip-text. That option OCRs only the pages that have no text yet.

For one image, call Tesseract directly. For a PDF of many scans, prefer OCRmyPDF so the text stays tied to pages.

Install the Tesseract language packs you name with -l. After OCR, read a few pages. Skew, handwriting, stamps, and tiny footnotes still fail, and those pages need a person.

Tables and layout

Simple extractors read left to right. Two columns become one scrambled column. A table becomes a sequence of cell values with the row and column breaks gone. Headers and footers get glued onto the first and last line of every page.

For a report whose meaning is in the tables, use a tool that emits a Markdown table or structured cells, then spot-check every important table against the PDF. If a table is the contract, keep the PDF page number in the text so someone can open the original.

Extraction tools

  • pdftotext (Poppler). Fast, and the right start for ordinary text PDFs. Weak on complex layout.
  • PyMuPDF. A Python library for page-by-page text, images, and positions. Use it when you want page numbers and a script you control.
  • Docling. Converts PDFs and several office formats to Markdown or JSON, with attention to reading order and tables. Current docs show docling convert policy.pdf --to md; older releases used docling policy.pdf. Trust docling --help on your install.
  • Unstructured. Splits a document into elements such as title, paragraph, and table, which are natural boundaries for chunking.
  • Marker. Converts a PDF to Markdown in one pass, including many tables and multi-column pages.

Step 6

Emails

Why Decisions often live in mail, and a raw export is full of signatures, legal footers, and the same quoted history repeated under every reply. Indexed that way, one thread crowds out everything else.

Just do this

Save the threads you need, not a whole private mailbox. Keep each thread together, in date order, with the sender and the date on every reply. Leave the saved message untouched.

  • Gmail, on the web. Open the message, open the three-dot More menu, and choose Download message. That saves an .eml file.
  • Apple Mail. Choose File > Save As and set the format to Raw Message Source, which is one message as an .eml file. Dragging the message onto a folder saves the same kind of file.
  • Thunderbird. Choose File > Save As > File.
  • Outlook. In new Outlook, open the message and choose More actions > Save as. In Outlook on the web, choose More actions > Download. The saved file is one message; the ending depends on the version.

For the copy you upload, drop repeated quoted replies and a legal footer you see on message after message, and keep the sender, the recipients, and the date. Save attachments next to the thread, and skip logos.

Power-user version: full notes for this step

How

Export .eml, .mbox, or .pst

  • .eml is one message per file. It is the easiest form to process and to cite.
  • .mbox is many messages in one file. Thunderbird and Google Takeout mail use it.
  • .pst is an Outlook archive. Convert it before ingestion. readpst (from libpst) can write one file per message with an extension such as .eml.

Keep the exported originals. Build a separate text copy for the index.

Keep threads together

Group messages with the Message-ID, In-Reply-To, and References headers. Sort each thread by date, and write one Markdown file with a heading per message. When those headers are missing, group by subject after you strip prefixes such as Re:, Fw:, Fwd:, and Aw:, and expect a few unrelated messages to land together. Check those.

Attachments

Save attachments next to the parent message, with the message id or date in the file name. List those file names in the message text so the link survives. Convert or OCR an attachment the same way you would if it had arrived on its own: a contract PDF follows step 5, a sheet follows step 8. Skip logos, tracking pixels, and decorative images, and note that you skipped them.

Signatures, disclaimers, and quoted replies

Clean the text copy, and leave the .eml untouched.

  • Drop lines that start with >. They repeat an earlier message that you already store once in the thread file.
  • Drop a trailing block that begins with the conventional signature mark -- followed by a space, when that mark is present.
  • Drop legal footers you have listed, once you can see the same paragraph on message after message.

Read a sample of threads after the cleaner runs. Some clients quote without >. Sometimes the only statement of a decision sits in a signature or a quoted blob. Fix those by hand, or rely on the thread file, which already contains the earlier message a single time.

Keep sender, recipient, and date

Copy From, To, Cc, Date, Subject, and Message-ID into the text header. The body cleaner has to leave those fields alone. Bcc is often missing on mail you received; leave it out rather than guessing. These fields are how someone checks an answer against the real message.

Step 7

Text, Word, and office files

Why A .docx or .odt file is a package of XML. Models need the words and the headings. The wrong encoding turns accents into junk and can split a word so search misses it.

Just do this

You can upload a Word file as it is. To make a PDF whose words stay selectable, in Word choose File > Save As or Save a Copy and pick PDF, or choose File > Export > Create PDF/XPS. In LibreOffice, choose File > Export As > Export as PDF. For a plain text file, save it so accents and quotes still look right; the full notes below use UTF-8 for that. Keep the original office file if people still edit there.

Power-user version: full notes for this step

How

Convert Word, ODT, RTF, and HTML to Markdown so headings stay headings. Pandoc is the general tool. --wrap=none avoids hard line breaks in the middle of sentences.

MarkItDown converts Office files to Markdown for text pipelines, including Word, PowerPoint, and Excel. Use it when you want one command across those formats. For slides, see step 9. For a large sheet, prefer the CSV rules in step 8.

Use plain text when the source is already prose with no headings. Keep the original Office file if people still edit there. The Markdown is the build you index.

Encoding and line endings

  • Save every text file as UTF-8.
  • On Linux and many other Unix systems, file --mime-encoding prints a guess. Open the file and look at accents, quotes, and dashes before you trust the guess.
  • Convert a known legacy encoding with iconv. Let the command fail if the bytes do not match, so a bad guess is visible.
  • Use LF line endings (\n). dos2unix converts a file from CRLF. In Git, a .gitattributes line of * text=auto normalizes text files on commit.

Step 8

Spreadsheets and CSV

Why A worksheet is often several tables, a chart, and a title stuffed into one grid. Retrieved row by row, that mix has no stable meaning.

Just do this

Put one table on each sheet you export. Use a single header row, with a short unique name on every column, and take merged cells and totals out of the data. In Google Sheets, choose File > Download > Comma-separated values (.csv). In Excel, choose File > Save As or Save a Copy and pick a CSV type; Microsoft’s help says the types you see depend on the sheet, and a CSV save writes the active sheet only. Prefer a type whose name includes UTF-8 when it is listed, so accents survive. Write dates as year-month-day. Beside the file, note what one row represents and what each column means.

Power-user version: full notes for this step

How

  • Put one table in each sheet you export. If a sheet stacks two tables under a chart, split them into two CSV files and describe the chart in a sentence, or leave the chart out.
  • Use a single header row. Names are short, unique, and readable: invoice_date, not Column1 and not two columns both called Date.
  • Unmerge cells inside the table. Keep totals out of the data file. If you need a total, write it in the column note.
  • Export each table to CSV in UTF-8. Write dates as YYYY-MM-DD. Store numbers without currency signs, and put the unit in the column name or the note (amount_usd).
  • Describe the columns in a short note beside the CSV: what one row represents, what each column means, and the allowed values when they are a small set.
  • When the formulas themselves matter, keep the workbook and also export the values.

Step 9

Images, slides, and scans

Why A chart, a photo, and a slide made of pictures are invisible to text search until someone describes them or OCR reads the words on them.

Just do this

Write a caption for every picture that carries meaning, and keep it in a text file next to the image or under the figure. Say what it shows. A file name is not a caption. For a photo of a page, use the recognition steps in Start here, and type the words yourself when the result is garbled, which is common for a whiteboard. For slides, upload the PowerPoint file, or in PowerPoint choose File > Export > Create PDF/XPS (or File > Save As, then PDF) so words on the slides are real text. Add a caption when a slide is mostly a picture.

Power-user version: full notes for this step

How

  • Write alt text or a caption for every image that carries meaning. Say what it shows and the figure that matters (“network diagram: failover path is backup-east, added March 2024”). A file name is not a caption.
  • Store the caption in a sidecar text file (network-diagram.txt) or under the figure in the Markdown you already produced.
  • For slides, write one Markdown section per slide. Include the slide number, the title, the body text, and the speaker notes. MarkItDown reads PPTX files. Add your own caption when a slide is mostly a picture.
  • OCR page scans with Tesseract or OCRmyPDF, as in step 5. A photograph of a whiteboard often comes back garbled. Transcribe the parts you need when the OCR text is wrong.

Step 10

Chunking

Why Retrieval works on passages, and models read a limited amount of text at once. A whole manual as one blob is hard to retrieve. A single sentence with no heading is hard to understand.

Just do this

With about 20 files in ChatGPT, Claude, or NotebookLM, leave each document whole. Those products split long files on their own. If an answer misses the right section, break the document at its headings and put the document title and the heading at the top of each piece. Keep a small table in one piece, and repeat the column names if you must split a large table. Keep a warning in the same piece as the rule it qualifies.

Power-user version: full notes for this step

How

  • Split on headings and sections first. If a section is still very long, split it into passages of a few hundred words. Test that size with real questions (step 12) before you tune it.
  • When a split would cut a sentence or a rule in half, repeat the last sentence or two at the start of the next passage. A large overlap mostly stores the same text twice.
  • Put the heading path on every chunk (“Travel policy > Hotels > International”), plus the document title, the source path or URL, and a page or slide number when you have one.
  • Keep a small table in one chunk. For a large table, chunk by row and repeat the column header and the table name on each piece.
  • Keep a warning with the rule it qualifies. Keep the sentence that introduces a list with that list.
  • Give each chunk a stable id, such as travel-policy#hotels-international, so an update replaces that passage instead of adding another copy.

Step 11

Privacy and security

Why A retrieval system quotes what you indexed. Anything in the corpus can show up in an answer, and sending that text to a hosted model is a disclosure. This section is practical hygiene, not legal advice.

Just do this

Before you upload, remove national ID numbers, payment cards, bank details, home addresses, health details, passwords, and secret keys when the document still answers the question without them. Leave out any file whose readers are a smaller group than the people who can use the chat. Uploading sends a copy to the company that runs the chat. If these files are confidential, keep them off a public chat. A permission label does nothing until the app that runs the search enforces it.

Power-user version: full notes for this step

How

Decide the audience before you add files. An assistant for one team and a bot on a public site are different corpora. Match the corpus to the people who can query it.

Redact personal data you do not need

Remove national ID numbers, payment card numbers, bank details, home addresses, health details, passwords, and API keys when the document still answers questions without them. Presidio can flag likely personal data. Treat its hits as a review queue. It misses things, and it also flags names you may need to keep, such as the author of a policy. A person reviews high-risk collections.

Honor access rights

If a folder is limited to HR, leave it out of a company-wide index. Store the permission label from step 4, and enforce it in the application that runs the query. A label in the file is not a control on its own. Filters belong in the search layer, where a user only retrieves chunks they are allowed to read.

Leave these out

  • Passwords, keys, tokens, and connection strings.
  • A full personal mailbox, when the task only needed a shared team inbox.
  • Documents whose readers are a smaller group than the people who can query the index.
  • Material a contract, a statute, or a legal hold says you cannot process this way. Ask the people who own that decision.
  • Customer content your agreement does not allow you to send to a model provider.

Know where the index and the model run. Text sent to a third-party API leaves your network. Prefer a setup that matches the rule you already follow for that data.

Step 12

Quality checks

Why Extraction fails quietly. A script can finish with empty pages, reversed columns, or a running header glued into every chunk.

Just do this

Open the original beside the text for a few files: one ordinary document, one scan, one table, one email thread, and one slide deck, if you have them. Read the start, a page from the middle, and one table. Then ask three questions you already know the answer to. If the reply is empty or wrong, fix the file first. Typical causes are missing words, a bad split, or an old copy still in the set.

Power-user version: full notes for this step

How

  • Spot-check a sample of each file type, including the awkward ones: a scan, a two-column PDF, a spreadsheet, a long email thread, and a slide deck.
  • Open the original beside the text. Read the start, a page from the middle, one table, and one page that has a header, a footer, or footnotes.
  • Look for empty output, damaged characters (a UTF-8 file read as Latin-1, or the reverse), missing headings, a table read across the row instead of down it, and the same disclaimer repeated on every page.
  • Write questions people actually ask. For each one, record the document and the passage that should answer it. Run the questions through search or your retrieval tool.
  • On a miss, fix the file or the chunk first. Typical causes are missing text, a bad split, or an old copy still in the index beside the new one. Change the prompt after those are fixed. Keep the question list and run it again after each pipeline change.

Step 13

Keeping it fresh

Why A stale corpus answers with last year’s policy. Two editable copies drift apart the week someone updates only one of them.

Just do this

Edit the document in one place. The file you upload is a copy of that place, not a second copy to edit. When the source changes, replace the uploaded copy and remove the old one so the chat cannot quote last year’s version. Check prices and procedures on a schedule you will keep. A signed contract usually changes only when someone replaces the file.

Power-user version: full notes for this step

How

  • Keep a single source of truth. People edit the policy site, the contract folder, or the sheet. The text you index is a build from that source, not a second place to edit.
  • When a source changes, re-extract that document and replace its chunks under the same id. Leave the old text out of the index.
  • Log each change: date, document id, old and new hash, and who or what job ran it. Git history is enough when the text files live in Git. Otherwise append one line to a log.
  • When a document is superseded, remove it from the index or mark it superseded and exclude that mark from normal search. Keep the file in an archive folder if retention says you must hold it.
  • Review collections that change often, such as prices and procedures, on a schedule you can keep. Signed contracts usually change only when someone replaces the file.

Step 14

One-page checklist

Why A short list is what you can actually run before you call a corpus ready. Print this section, or keep it in the collection README.

Just do this

Tick this list before you call the folder ready.

Scope

  • Locations are listed: drives, mail, wikis, local folders.
  • Each collection has an owner, and the corpus has an owner.
  • In and out of scope are written down, with a reason.

Cleanup, names, and metadata

  • Exact duplicates are removed or parked outside the index.
  • One current version is chosen for each document.
  • Junk files are gone (.DS_Store, Thumbs.db, lock files, empties).
  • Folders are shallow, and names are stable. ISO dates lead when the date matters.
  • Each document has title, date, author, source, type, and permissions.

Conversion

  • Text PDFs are extracted. Scans are OCR’d before extraction.
  • Tables were checked against the original, not only the body text.
  • Mail is .eml or .mbox. PST files are converted.
  • Threads stay together. Attachments sit beside the message.
  • Signatures, disclaimers, and quoted replies are stripped on the text copy only.
  • Sender, recipients, and date are kept.
  • Office files are Markdown or UTF-8 text. Encoding is UTF-8. Line endings are LF.
  • Each sheet export is one CSV table, with a column note.
  • Images and slides have a caption, alt text, or OCR text.

Chunks, access, and upkeep

  • Chunks follow headings. Each chunk has its heading path, source, and id.
  • Personal data you do not need is redacted. A person reviewed the high-risk sets.
  • Secrets and out-of-audience material are left out.
  • Permission labels are stored, and search enforces them.
  • A sample of each file type was compared with the original.
  • Real questions return the right passage. Misses were rechecked after fixes.
  • The corpus is rebuilt from the source of truth.
  • Changes are logged. Superseded documents are out of normal search.

Glossary

One sentence for each word this guide uses in a special way.

OCR
OCR, short for optical character recognition, is the step that reads letters in a picture or a scan and saves them as text you can select and search.
Chunk
A chunk is a short passage cut from a longer document so search can return that part instead of the whole file.
Retrieval (RAG)
Retrieval, also called RAG (retrieval-augmented generation), finds passages in your files and hands them to the model so the answer comes from those passages.
Metadata
Metadata is facts stored with a document, such as its title, date, author, and who may read it.
Encoding
Encoding is the rule a text file uses to store letters as bytes, and the wrong rule turns accents and punctuation into junk.
UTF-8
UTF-8 is a text encoding that can store almost every written language, and it is the encoding this guide asks you to use.
Line endings
Line endings are the invisible characters that mark the end of a line, and Windows and Unix systems write different ones.
.eml
An .eml file is one email message, including the sender, the recipients, the date, and the body.
.mbox
An .mbox file stores many email messages, one after another, and it is the form Thunderbird and Google Takeout use.
CSV
A CSV file, short for comma-separated values, is a plain-text table where each line is a row and commas separate the columns.
Sidecar file
A sidecar file is a small text file kept beside a document, usually with the same name, that holds a caption or notes about that document.
Index
The index is the searchable copy of your documents that the question-answering system actually looks through.
Corpus
A corpus is the set of documents you have decided to include and prepare.
Markdown
Markdown is a plain-text way to mark headings, lists, and links so both people and tools can see the structure.
Text layer
A text layer is the hidden, selectable words stored inside a PDF, behind the picture of the page.
